## Headline result

**Not promotable at default optimizer weights.** `ab_report.json["promotable"] == false`.

### Hard constraints (`ab_report.json["old"]["verification"]` / `["new"]`)

Baseline has 113 violations, new candidate has 112 (one fewer — the
optimizer doesn't reduce these because it only reassigns teams within the
existing skeleton, it doesn't touch dates/arenas/participation counts):

- 110× `participation_target_mismatch` — many teams play 6 tournaments when
  the age group's before/after-Christmas config split implies 10 (e.g. JU12:
  `before_christmas: 5, after_christmas: 5` in `problem.json`, but teams
  participate 6 times in both candidates). **Unresolved** — needs
  investigation into whether this is a real Stage 3 planning shortfall or a
  target-resolution mismatch between the checkpoint and the current config.
  Present identically in both candidates (participation counts are preserved
  by construction in the optimizer), so it isn't a regression, but it's a
  pre-existing correctness question worth chasing before promoting anything.
- 2× `arena_interval_conflict`, 1× `duplicate_participation_same_date` —
  both pre-existing in baseline, unchanged by the optimizer.

## Interpretation for whoever picks this up

At `stage3_optimizer.DEFAULT_WEIGHTS`, the optimizer over-indexes on
opponent-pair diversity at the expense of turnaround spacing and same-club
pairing count — the *opposite* tradeoff direction from the manual experiment
described in issue #257 (which improved turnaround while holding same-club
pairings flat). Two follow-ups, not yet attempted:

1. Retune `DEFAULT_WEIGHTS` in `tournament_scheduler/stage3_optimizer.py`
   (raise `gap_under_7`, `gap_under_14`, `same_club_pairing` relative to
   `pair_repeat`) and re-run `plan ab` to see if a better Pareto point exists
   that doesn't regress turnaround/same-club metrics.
2. Investigate the 110 `participation_target_mismatch` violations — root
   cause not yet determined.

Re-run with `scripts/rvv-miniputt` or
`python3 -m tournament_scheduler.cli.rvv_cli plan ab --work-dir .pipeline`
against the live checkpoint for fresh numbers; this snapshot will drift as
the pipeline is re-run.
