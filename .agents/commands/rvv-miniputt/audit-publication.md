# Publication-scoped semantic audit and recovery (lazy-loaded)

Load for every request to publish/republish an already published or sealed season, especially when semantic audit reports FAIL/INCOMPLETE or repeated historical season debt. This procedure orchestrates existing repository actions; it does not grant permission to bypass a deterministic publication gate. Also read `publish.md`, `republish.md`, `season-delivery.md` and the shared RVV semantic audit contract.

## Choose the right scope
Distinguish (1) the full-season completion/quality audit (`season audit --json`), (2) semantic assessment of the exact exported public projection, and (3) deterministic publish preflight. Full-season planning obligations remain visible but are not automatically evidence that an unchanged, unpublished obligation invalidates an unrelated published-tournament correction. An audit of an incremental republish must compare the authoritative last-published snapshot to the current canonical/export projection, including every added, removed or changed tournament. Never assess only the one named request when other changes are bundled into the export.

## Execute the publication investigation without asking for routine next steps
1. Resolve current lifecycle, published run and revision through `season lifecycle --json`, `season publication-evidence --json`, and `operator publish-history --json`. Inspect the current exact export fingerprint, freshness and XLSX/HTML parity. Never infer baseline from `latest/` or an arbitrary export.
2. Check canonical reconciliation and the complete published-to-canonical delta. For every changed public tournament, verify stable ID, exact date/start/end/arena/host, roster, cancellation, and accepted source-backed booking evidence, plus protections/locks and relevant hard-safety findings. Check unchanged published entries remain stable. An absent or incomplete scrape is not proof that an accepted booking is invalid.
3. Use `operator audit-context` and selective `operator audit-evidence --item/--tournament/--club/--category/--unresolved` to obtain evidence bound to this export; compare the last accepted publication and known debt. Never silently submit a different verdict merely because the operator wants publication.
4. Classify each concern with evidence as: global safety/integrity blocker; changed/included-tournament blocker; unresolved cross-tournament effect (including hosting responsibility transfer); unchanged historical planning debt outside the public delta; or missing evidence. In particular investigate the owner check underlying `hosting_responsibility`: it cannot be dismissed merely because ordinary findings omit item detail.
5. If exact public projection is safe and the repository's currently supported semantic audit contract permits `PASS` or `REVIEW_REQUIRED`, submit an honest fresh fingerprint-bound assessment with remaining debt visible, then continue through the existing canonical gate. A REVIEW_REQUIRED still requires the repository's specific operator approval, not implied authorization from the request to publish.
6. If the actual canonical audit or publish preflight remains FAIL/INCOMPLETE, stop the public action. Do not issue a fake PASS, edit audit JSON, fabricate waivers, suppress findings, alter canonical plan to silence debt, or call `--confirm-public` as an audit bypass. Report the precise contradictory check and route its implementation to issue #541 (tournament-scoped eligibility/gate); preserve the export and the last public run. Do not demand that unrelated Jar/JU8 work be completed or ask the operator to choose between unrelated repair and indefinite hold.
